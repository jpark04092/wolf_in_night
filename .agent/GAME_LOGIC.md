# 게임 로직 및 상태 머신 명세서 (Game Logic & Rules)

## 1. 5단계 상태 머신 생명주기 (State Machine Lifecycle)

```
[ 대기실 (WAITING) ] 
       │  ├─ 참가 인원수별 고정 정렬 덱 뱃지 표시 (렌더링 시 레이아웃 쉬프트 원천 차단)
       │  ▼ (방장: 게임 시작 클릭 / shuffleDeck으로 덱 1회 무작위 셔플 및 분배 / 방장 로컬 players 상태 즉시 갱신)
[ 밤 단계 (NIGHT) ] 
       │  ├─ [1단계: 시작 직업 확인 (Card Reveal)]: state.currentStep === null 상태로 5.0초간(Fast Mode 3.0초) 전원 비밀 시작 직업 카드(RoleRevealModal) 확인
       │  ├─ 4x4 메모리 미니게임 전원 플레이 (블러핑 은폐)
       │  ├─ 실시간 스텝 진행 바 (직업 확인 중: "비밀 직업 카드를 확인하고 있습니다...", 직업 차례 중: "고요한 정적 속에서 밤이 흐르고 있습니다...")
       │  ├─ [2단계: 직업별 순차 액션 (WEREWOLF → SEER → ROBBER → TROUBLEMAKER → INSOMNIAC)]
       │  │  • 늑대인간(WEREWOLF): 직업 확인 모달 종료 직후 NightActionModal 즉시 팝업, 동료 늑대인간 병렬(Promise.all) 및 낙관적 UI 즉각 렌더링
       │  └─ 스마트 차등 타이머 & 분산 자가 치유(Self-Healing):
       │     • 직업 확인 단계 (currentStep: null): 5.0초 (Fast Mode 시 3.0초) 후 자동 WEREWOLF 전진
       │     • 사람 플레이어 직업: 14초 세이프가드 (모달 완료 시 즉시 전진)
       │     • 가상 봇 플레이어 직업: 2초 (1.2초 시점에 스왑/조회 자동 실행)
       │     • 플레이어 미배정 직업(중앙 카드): 블러핑 은폐 3.5초 대기 (Fast Mode 시 0.8초)
       │     • 호스트 탭 스로틀링 대비: 타임아웃 + 2.5s 초과 시 1번 활성 플레이어 대리 전진
       ▼ (마지막 직업 완료 또는 타이머 만료 시 자동 전환)
[ 아침 토론 (DAY_DISCUSSION) ] 
       │  ├─ 300초(5분) 토론 카운트다운 타이머 (테스트 모드 시 무제한)
       │  ├─ 참가 직업 & 밤 액션 순서 타임라인 (Night Action Timeline) 실시간 제공:
       │  │  • 이번 판 덱에 포함된 전체 역할 목록(`state.deck` 또는 기본 덱) 뱃지 요약
       │  │  • 밤 액션이 있는 참가 직업들의 공식 실행 순서(Step 1~N) 및 직업별 토론 추론 핵심 팁
       │  │  • 밤 행동이 없는 참가 직업(마을주민, 무두장이) 별도 구분 명시
       │  │  • 교환의 타임라인(강도 → 말썽쟁이 → 주정뱅이), 예언자 vs 불면증환자의 시점 차이 추론 가이드
       │  ├─ 블러핑 화면 인증 원천 차단: 자신의 시작 직업(`initialRole`)을 아침 토론 화면에 일체 표시하지 않아, 토론 중 타인에게 화면을 직접 보여주며 직업을 인증하는 행위를 원천 방지
       │  └─ 스마트폰 최적화 접기/펼치기 아코디언 UI
       ▼ (방장: 투표 시작 클릭)
[ 투표 단계 (VOTING) ] 
       │  └─ 각자 의심자 1인 지목 (제출 전 자유로운 선택 변경 가능, 제출 시 확정 잠금) 및 votes/{userId}.txt 기록
       ▼ (방장: 결과 발표 클릭 / 투표 집계)
[ 결과 발표 (RESULT) ] 
       │  ├─ 최다 득표자 처형 및 승리 진영 발표 (시민 vs 늑대 vs 무두장이)
       │  └─ 전체 시작 직업 및 바뀐 최종 직업 일괄 공개
       ▼ (방장: 새 게임 시작 클릭)
[ 대기실 복귀 (WAITING) ]
```

## 2. 밤 단계 직업 실행 순서 (Night Action Order) 및 토론 추론 원칙

`ROLES` 상의 공식 순서는 보드게임 원작의 공식 룰을 따르며, 아침 토론 시 **참가된 역할들의 실행 순서와 교환 타임라인**을 역추적하는 핵심 단서가 됩니다.

| 순서 (`nightOrder`) | 직업 ID | 이름 | 진영 | 밤 행동 명세 | 토론 추론 핵심 팁 (`deductionTip`) |
| :---: | :--- | :--- | :--- | :--- | :--- |
| **1** | `WEREWOLF` | 늑대인간 | 늑대 | 동료 늑대인간 확인. 자신이 유일한 늑대일 경우 중앙 카드 3장 중 1장을 확인 가능. | 늑대들은 서로의 정체를 확인했습니다. (외톨이 늑대는 중앙 1장 확인) |
| **2** | `MINION` | 하수인 | 늑대 | 늑대인간이 누구인지 확인 (늑대인간은 하수인이 누구인지 알 수 없음). | 늑대인간이 누구인지 알고 있으나, 늑대들은 하수인을 모릅니다. |
| **3** | `SEER` | 예언자 | 시민 | 다른 플레이어 1명의 카드를 보거나, 중앙 카드 3장 중 2장을 확인. | **교환이 발생하기 전 최초의 카드**를 확인했습니다. |
| **4** | `ROBBER` | 강도 | 시민 | 다른 플레이어 1명의 카드를 가져오고 내 카드를 넘김. 훔쳐온 새 카드를 확인. | 다른 플레이어의 카드를 훔쳐오고 내 카드를 넘김. (**1차 교환 발생**) |
| **5** | `TROUBLEMAKER`| 말썽쟁이 | 시민 | 다른 플레이어 2명을 선택하여 두 카드를 맞바꿈 (카드를 볼 수는 없음). | 강도가 훔친 뒤, 다른 두 플레이어의 카드를 맞바꿈. (**2차 교환 발생**) |
| **6** | `DRUNK` | 주정뱅이 | 시민 | 자신의 카드를 중앙 카드 1장과 맞바꿈 (카드를 볼 수는 없음). | 말썽쟁이 교환 직후 중앙 카드와 보지 않고 맞바꿈. (**본인도 현재 직업 모름**) |
| **7** | `INSOMNIAC` | 불면증환자 | 시민 | 밤이 끝날 때 자신의 카드가 교환되었는지 최종 확인. | 강도·말썽쟁이·주정뱅이의 모든 교환이 끝난 뒤 **최종 자신의 카드**를 확인. |
| - (0) | `VILLAGER` | 마을 사람 | 시민 | 밤 행동 없음. | 밤 동안 아무런 행동도 하지 않고 잠을 잤습니다. |
| - (0) | `TANNER` | 무두장이 | 중립 | 밤 행동 없음 (처형당하면 단독 승리). | 밤 동안 행동이 없으며, 낮 투표에서 자신이 처형당해야 단독 승리합니다. |

### 토론 추론 3대 핵심 원칙:
1. **카드 교환의 선후 관계**:
   - `강도 (Step 4)` → `말썽쟁이 (Step 5)` → `주정뱅이 (Step 6)` 순서로 카드가 이동합니다.
   - 강도가 먼저 목표 플레이어의 카드를 가로채고 자신의 강도 카드를 남기며, 이후 말썽쟁이가 플레이어 둘의 카드를 섞고, 마지막에 주정뱅이가 중앙 카드와 교환합니다.
2. **관측 시점의 차이 (예언자 vs 불면증환자)**:
   - **예언자 (Step 3)**는 교환이 전혀 일어나지 않은 **태초의 상태(Initial Role)**를 보았습니다.
   - **불면증환자 (Step 7)**는 강도, 말썽쟁이, 주정뱅이의 **모든 교환이 완료된 최종 상태(Final Role)**를 보았습니다.
3. **주정뱅이의 불확실성**:
   - 주정뱅이는 중앙 카드와 맹목 교환을 하였으므로, 게임이 끝날 때까지 본인조차 자신의 최종 정체를 알지 못합니다.

## 3. 블러핑 강제 은폐 기법 (4x4 메모리 카드 미니게임 및 상태 익명화)

* **문제점**: 오프라인에서 모바일 기기로 한밤의 늑대인간을 플레이할 경우, 밤에 본인 턴인 플레이어만 화면을 탭하거나 불빛이 바뀌어 정체가 즉각 탄로남. 또한 상단에 현재 행동 중인 직업명이 뜨면 탭 타이밍이나 경과 시간으로 정체가 유추됨.
* **해결책**:
  * **4x4 메모리 카드 맞추기 게임 강제 활성화**: 밤 단계가 시작되면 모든 플레이어가 쉼 없이 카드를 터치하여 손가락 움직임으로 직업을 유추할 수 없습니다.
  * **밤 액션 직업명 완전 은폐**: 최상단 헤더 뱃지(`"밤 (진행 중)"`) 및 진행 상태 표시줄(`"고요한 정적 속에서 밤이 흐르고 있습니다..."`) 어디에도 특정 직업명을 일체 노출하지 않고 중립적으로 표시합니다.
  * **반투명 액션 오버레이**: 본인 턴이 오면 메모리 게임 위에 반투명(`backdrop-blur`) 액션 모달이 덧씌워져 포커페이스를 유지한 채 은밀히 행동을 마칠 수 있습니다.
  * **아침 토론 시작 직업 표시 배제 (화면 인증 원천 차단)**: 토론 및 블러핑 중 자신의 스마트폰 화면을 타인에게 보여주어 "내 화면에 시작 직업이 OOO로 뜬다"며 신원을 물리적으로 증명(인증)하는 행위를 원천 방지하기 위해, 아침 토론 화면(`DiscussionView`)에서 개인별 시작 직업 제시를 완전히 제거하고 모든 참가자에게 동일한 추론 타임라인 및 덱 정보만 제공합니다.

## 4. 안전한 `role` 프로퍼티 원자적 교환 (Safe Role Property Swapping)

강도(Robber)와 말썽쟁이(Troublemaker)가 플레이어 간 카드를 맞바꿀 때, WebDAV 파일 전체(`user_{id}.json`)를 `MOVE`하면 유저의 닉네임(`displayName`), 시작 직업(`initialRole`), 하트비트(`lastSeen`)까지 왜곡되어 정체성이 파괴되는 버그가 발생합니다.

이를 방지하기 위해 **오직 카드를 나타내는 `role` 프로퍼티만 상호 교체하여 `PUT`**합니다:

```
[ 플레이어 A ] role: "ROBBER"   , initialRole: "ROBBER", displayName: "철수"
                                ↕ (role 값만 안전하게 교환)
[ 플레이어 B ] role: "VILLAGER" , initialRole: "VILLAGER", displayName: "영희"
```

1. `webdav.get(fileA)` 및 `webdav.get(fileB)`로 두 유저의 최신 상태 조회.
2. `webdav.put(fileA, { ...userA, role: userB.role })`
3. `webdav.put(fileB, { ...userB, role: userA.role })`
* **무결성 보장**:
  - `initialRole`은 게임 시작 시점 부여된 후 **절대 변경되지 않으므로**, 카드를 빼앗긴 사람에게 강도 팝업이 다시 뜨는 일이 원천 차단됩니다.
  - 유저의 `displayName`, `avatarId`, `lastSeen`이 완벽히 보존되므로 강도 대상 목록에서 유저가 사라져 정체가 스포일러되는 문제가 발생하지 않습니다.

## 5. 승패 및 처형 판정 로직 (Victory Conditions)

1. **무두장이(Tanner) 사망 여부 최우선 판정**:
   * 처형된 플레이어 목록(`killedUserIds`)에 무두장이가 포함되어 있다면 다른 조건과 무관하게 **무두장이 단독 승리**.
2. **늑대인간이 존재하는 게임**:
   * 처형된 사람 중 최소 1명 이상이 `WEREWOLF`인 경우: **마을 사람 팀 승리**.
   * 처형된 사람 중 늑대인간이 전혀 없는 경우: **늑대인간 팀 승리**.
3. **평화의 마을 (중앙에 늑대인간 2장이 모두 들어가 게임 내 늑대인간이 0명인 경우)**:
   * 아무도 처형되지 않은 경우 (동점 분산으로 0명 처형): **마을 사람 팀 승리**.
   * 무고한 마을 사람이 처형된 경우: **늑대인간 팀(유령) 승리**.

## 6. 브라우저 세션 복원 및 동기화 무결성 규칙 (Session & Presence Integrity)

1. **새로고침 시 직업 상태 불변 원칙**:
   - 게임 진행 중(`NIGHT`, `DAY_DISCUSSION`, `VOTING`, `RESULT`) 브라우저 새로고침이나 네트워크 재연결이 발생하더라도, 유저의 배정된 직업(`role`, `initialRole`)은 절대로 초기화(`VILLAGER`)되어서는 안 됩니다.
   - 클라이언트는 서버의 기존 유저 카드를 탐색하여 직업 정보를 안전하게 복원합니다.
2. **재접속 및 난입 제한 규칙**:
   - 대기실(`WAITING`): 방에 기존 카드가 없더라도 신규 플레이어로 정상 등록됩니다. 단, 이미 활성(온라인) 상태인 동일한 닉네임(ID)의 플레이어가 존재할 경우 입장이 차단되고 로비에 머무릅니다.
   - 인게임 단계(`WAITING` 외): 기존 유저 카드가 등록되어 있는 플레이어만 재연결 복원이 허용되며, 미등록 외부 사용자의 게임 도중 난입은 차단되고 로비로 안전하게 안내됩니다.
3. **오프라인 유령 플레이어 판정 및 정리**:
   - 모든 활성 클라이언트는 4초 주기로 하트비트(`lastSeen`) 및 `sessionId`를 갱신합니다.
   - 12초 이상 하트비트 갱신이 없는 플레이어는 `isOnline: false`로 처리됩니다.
   - 방장은 대기실에서 12초 이상 오프라인 상태인 유령 플레이어를 `[강퇴]`하여 룸 정원을 정리할 수 있습니다.
   - 동일 닉네임 사용자가 재입장할 때 이전 비활성 세션(12초 초과 미응답)은 자동 제거되어 중복 플레이어 참가를 방지합니다.
4. **동일 ID 다중 탭/다중 기기 동시 접속 차단**:
   - 동일한 브라우저 세션 ID(`myId`)로 복수의 탭이 동시에 대기실에 접속하려는 경우, `BroadcastChannel` 통신을 통해 신규 탭의 접속을 차단합니다.
   - 다른 기기 또는 브라우저에서 동일한 유저 카드로 접속하여 `sessionId`가 변경된 경우, 기존 탭은 안전하게 연결을 해제하고 사용자에게 안내합니다.

## 7. 방장 권한 위임 및 자가치유 규칙 (Host Handover & Succession)

1. **대기실 리스트 순위 기반 방장 위임 원칙**:
   - 방장이 대기실을 퇴장할 경우, 접속자 목록의 다음 실제 플레이어(`activeHumans[0]`)에게 방장 권한(`hostId`)이 즉시 위임됩니다.
   - 방장 권한을 인계받은 새 방장은 게임 시작, 봇 추가/제거, 빠른 진행 모드 제어 권한을 즉시 획득합니다.
2. **비정상 종료 시 분산 선출 자가치유**:
   - 방장이 명시적으로 퇴장하지 않고 탭을 닫거나 통신이 두절되어 오프라인이 된 경우, 남아있는 온라인 플레이어 중 목록 최우선 플레이어가 자동으로 방장을 승계하여 게임 진행이 멈추지 않도록 보장합니다.
3. **룸 소멸 및 정리 조건**:
   - 방에 실제 인간 플레이어가 0명이 되면 방 전체 디렉터리가 자동 소멸(`DELETE`)되며, 방이 종료된 경우 남아있던 게스트 화면에 안내 후 로비로 안전하게 회귀합니다.

## 8. 관리자 테스트 모드 및 타이머 제어 규칙 (Test Mode & Timer Freeze)

1. **타이머 바이패스 (Freeze) 규칙**:
   - `state.testMode === true`인 경우, 밤 단계(`NIGHT`)의 차등 타이머(인간 12초, 봇 2초, 미배정 3.5초/0.8초) 및 호스트 스로틀링 세이프가드에 의한 자동 스텝 전진이 완전히 차단됩니다.
   - 아침 토론 단계(`DAY_DISCUSSION`)의 300초 카운트다운 타이머가 무제한으로 고정되며, 방장이 수동으로 [투표 시작]을 누를 때까지 영구 대기합니다.
2. **수동 스텝 전진 (Manual Advance)**:
   - 밤 단계에서 각 직업의 행동이나 화면을 다중 탭으로 충분히 확인한 후, 상단에 노출되는 `[다음 밤 단계 진행 ⏩]` 버튼을 클릭하여 원하는 시점에 직업 스텝을 수동으로 전진시킵니다.
3. **하트비트 유예 시간 대폭 연장**:
   - 혼자 다중 탭을 전환하며 테스트할 때 백그라운드 탭의 비활성화로 인해 오프라인 판정 및 방장 권한이 의도치 않게 이양되는 것을 방지하기 위해, 테스트 모드 중에는 하트비트 판정 임계치를 12초에서 **180초(3분)**로 대폭 완화합니다.

## 9. 게임 종료 후 대기실 복귀 및 연속 재시작(리매치) 규칙 (Rematch & State Machine Reset)

게임 종료(`RESULT`) 화면에서 방장이 `[대기실로 돌아가기 (다시하기)]`를 클릭하거나 다음 게임을 시작할 때, 이전 게임의 잔여 데이터가 다음 판에 간섭하지 않도록 상태를 원자적으로 초기화합니다:

1. **대기실 복귀 시 WebDAV 데이터 초기화 트랜잭션 (`handleRestartGame`)**:
   - **룸 상태 초기화**: `state.json`을 `phase: 'WAITING'`, `currentStep: null`, `stepStartedAt: 0`, `killed: null`, `round` 보존으로 리셋합니다.
   - **투표 디렉터리 원자적 정리 (`clearVotesDirectory`)**: `/rooms/{roomId}/votes/` 폴더 내 개별 투표 파일(`.txt`)들을 조회하여 일괄 삭제합니다. 폴더 자체를 삭제 후 재생성하지 않음으로써 WebDAV 301/405/409 충돌을 방지하고 다음 게임의 투표가 안전하게 초기화되도록 보장합니다.
   - **유저 카드 역할 초기화**: 접속 중인 유저 및 봇의 `{userId}.json`에서 `initialRole` 필드를 제거하고 `role: 'VILLAGER'`로 리셋합니다. 이때 플레이어의 정체성(`displayName`, `avatarId`, `sessionId`, `lastSeen`)은 안전하게 보존됩니다.
2. **연속 게임 시작 시 직업 배정 및 모달 팝업 무결성 보장 (`syncState` & `handleStartGame`)**:
   - **게임 회차 추적 (`state.round` & `lastHandledRoundRef`)**: 각 클라이언트는 매 턴 갱신되는 `stepStartedAt` 대신 `state.round` 변경을 감지하여 새로운 게임 회차(Round)를 식별합니다. 이를 통해 테스트 모드에서 `[다음 밤 단계 진행]`을 누르거나 턴이 전진할 때마다 방장의 시작 직업 팝업(`RoleRevealModal`)이 반복해서 다시 열리는 버그를 원천 차단합니다.
   - **시작 직업 확인 모달(`RoleRevealModal`) 1회 활성화**: 새로운 게임 회차가 시작될 때만 모든 플레이어(방장 및 게스트)의 `hasConfirmedInitialRole`을 `false`로 리셋하여, 회차당 본인의 새로운 비밀 시작 카드를 전면 확인하고 확인 후에는 턴이 넘어가도 다시 뜨지 않도록 보장합니다.
   - **이전 게임 직업 고착 방지**: `myInitialRole`이 이전 게임의 역할로 고착되지 않도록 대기실 복귀 시 로컬 상태를 클리어하고, 새 게임 회차 시작 시 서버에서 새로 셔플되어 배정된 `initialRole`을 즉시 동기화합니다.
3. **게임 시작 중복 클릭 방지 (`isStartingGame`)**:
   - 방장이 `[게임 시작]` 버튼을 누르면 덱 셔플, WebDAV 카드 쓰기, 상태 전이 트랜잭션이 완료될 때까지 버튼이 비활성화되고 로딩 인디케이터가 표시되어 다중 요청 충돌을 방지합니다.
4. **결과 발표(`RESULT`) 단계에서의 재입장 허용**:
   - 게임 진행 도중 이탈했거나 브라우저를 새로고침한 플레이어가 결과 발표 화면에서도 방에서 튕기지 않고 대기실 복귀 및 다음 판 리매치에 원활하게 합류할 수 있도록 입장 검증 조건을 개선(`existingState.phase !== 'WAITING' && existingState.phase !== 'RESULT'`)하였습니다.
5. **두 번째 판 투표 정상화 보장 (`VotingView` & `clearVotesDirectory`)**:
   - 새 게임 시작 시 이전 판 투표 파일이 완전히 제거되고, `VotingView` 내부의 `selectedTarget` 및 `hasVoted` 상태가 `null`/`false`로 정상 초기화되어 두 번째 게임부터 투표 카드가 잠기거나 제출 버튼이 사라지는 현상을 원천 방지합니다.

## 10. 가상 봇(Bot) 추가 시 중복 이름 방지 및 동시성 락 규칙 (Bot Naming Deduplication & Concurrency Guard)

대기실에서 가상 봇 추가 시 이름 중복 및 비동기 레이스 컨디션에 의한 파일 충돌을 원천 차단하기 위한 무결성 규칙입니다:

1. **실시간 고유 닉네임 동적 탐색 (`handleAddBot`)**:
   - 단순 인덱스(`players.length + 1`) 기반 이름 지정을 폐기하고, 현재 방에 존재하는 모든 플레이어(인간 및 봇)의 `displayName` 목록(`existingNames`)을 Set으로 수집합니다.
   - 브라우저 새로고침(F5) 직후나 폴링 지연으로 인해 로컬 `players` 상태가 일시적으로 비어있을 때를 대비하여, WebDAV의 `/rooms/{roomId}/` 내 실제 파일들을 직접 조회하여 기존 이름을 완벽하게 수집합니다.
   - 확장된 봇 이름 풀(`['민수', '영희', '지우', '현우', '다은', '준호', '서연', '도윤', '하은', '예준', '유진', '시우']`)에서 **현재 방에 없는 첫 번째 이름**을 우선적으로 선택합니다.
   - 모든 프리셋 이름이 사용 중인 경우, `봇_1`, `봇_2`... 번호 증분 방식을 통해 절대 중복되지 않는 고유 이름을 생성합니다.
2. **연타 방지 비동기 락 (`isAddingBot`)**:
   - 방장이 `[봇 추가]`를 빠르게 더블 클릭하거나 연타할 경우, 첫 번째 요청이 WebDAV에 기록되어 화면에 반영되기 전까지 버튼이 `disabled` 상태로 전환되고 `"추가 중..."` 로딩 텍스트가 표시됩니다.
3. **낙관적 UI 업데이트 (Optimistic Update)**:
   - 봇 추가 시 `setPlayers`를 통해 즉시 로컬 상태에 새 봇 정보를 주입하여, 다음 클릭이나 연산 시 즉각 반영된 최신 목록을 참조하도록 보장합니다.
   - 봇 제거 시에도 `setPlayers`에서 해당 ID를 즉시 필터링하여 반응성을 극대화합니다.
4. **대기실 최대 인원 가드 (Max Players Cap)**:
   - 게임 인원이 10명 이상에 도달한 경우 `[봇 추가]` 버튼이 비활성화되어 덱 구성 한도를 초과하지 않도록 보호합니다.
